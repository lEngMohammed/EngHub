# EngHub

منصة تفاعلية من صفحة واحدة لمهندسي الحاسب والشبكات: مجتمع حي لمشاركة الأفكار والحلول، مع أدوات يومية تعمل داخل المتصفح.

🔗 **الموقع المباشر:** https://lengmohammed.github.io/EngHub

## المميزات

- **مجتمع مشترك بين الزوار:** نشر الأفكار والحلول (فكرة، حل برمجي، حل شبكي، سؤال) مع إعجابات وتعليقات لحظية عبر Firebase Firestore.
- **حاسبة Subnet / CIDR:** Network ID وBroadcast والقناع وأول وآخر عنوان وعدد العناوين المتاحة.
- **حاسبة زمن نقل الملفات:** من حجم الملف وسرعة الاتصال، مع خيار الحمل البروتوكولي.
- **مرجع المنافذ والبروتوكولات:** جدول قابل للبحث مع نسخ سريع.
- **طرفية محاكاة (Sandbox):** `ping` و`nslookup` و`traceroute` و`ipconfig` و`port`، وتعبيرات بايثون بسيطة، دون اتصال حقيقي.
- واجهة داكنة بطابع تقني، دعم كامل للعربية (RTL)، ومتجاوبة مع الجوال.

## التقنيات

HTML5 و JavaScript (Vanilla) · Tailwind CSS (CDN) · خط Cairo · Firebase (Firestore + Anonymous Auth)

## هيكل المشروع

```
index.html        الموقع كاملاً (واجهة + منطق + اتصال Firebase)
firestore.rules   قواعد أمان قاعدة البيانات
README.md         هذا الملف
```

## التشغيل محلياً

لا حاجة لتثبيت حزم. افتح `index.html` في متصفح حديث (يلزم اتصال بالإنترنت). للتجربة مع Firebase استخدم خادماً محلياً بسيطاً مثل `python3 -m http.server`.

## إعداد Firebase (مرة واحدة)

1. **Authentication ← Sign-in method:** فعّل **Anonymous**. دون هذه الخطوة لن يعمل النشر.
2. **Firestore Database:** أنشئ قاعدة بيانات بوضع Production.
3. **Rules:** الصق محتوى `firestore.rules` كاملاً واضغط **Publish**.
4. **تقييد مفتاح الواجهة:** من Google Cloud Console ← APIs & Services ← Credentials، افتح مفتاح المتصفح وقيّده بـ **HTTP referrers** على نطاق موقعك فقط (مع `localhost` للتجربة).
5. **(موصى به) App Check:** فعّل Firebase App Check مع reCAPTCHA v3 لتقليل الطلبات الآلية.

> مفتاح Firebase في الكود ليس سراً بطبيعته. الحماية الفعلية تأتي من قواعد الأمان وتقييد المفتاح.

## النموذج الأمني

- **هوية مجهولة:** كل زائر يحصل على معرّف مجهول، ولا نجمع اسماً حقيقياً ولا بريداً.
- **قواعد صارمة:** تُرفض أي مشاركة تخالف الشكل أو الأطوال أو الأنواع المسموحة (اسم حتى 30 حرفاً، نص حتى 600، تعليق حتى 200).
- **منع التلاعب بالأرقام:** الإعجاب مرة واحدة لكل مستخدم، والتعليقات إضافة فقط، ولا يمكن تعديل الأعداد يدوياً.
- **فاصل 15 ثانية** بين مشاركات المستخدم الواحد يُفرض في قاعدة البيانات نفسها.
- **حماية الهوية:** الأسماء المشابهة لاسم المالك محجوزة.
- **حماية الواجهة:** كل نص مستخدم يُهرَّب قبل العرض (XSS)، وتُزال محارف التحكم والتلاعب باتجاه النص. الطرفية تستخدم محللاً آمناً بدل تنفيذ JavaScript، ومنع التضمين في إطارات (Clickjacking) بقدر ما تسمح به الصفحة، مع سياسة CSP أساسية.
- **لا حذف من المتصفح:** حذف المشاركات المسيئة يتم يدوياً من Firebase Console، وهناك زر «إبلاغ» لكل مشاركة يرسل بريداً للمالك.

### حدود معروفة

- App Check غير مفعّل افتراضياً، فالحماية من السبام الآلي المتقدم جزئية حتى تفعّله.
- يمكن لمن يمسح بيانات المتصفح إنشاء هوية مجهولة جديدة، فمنع تكرار الإعجاب والفاصل الزمني يكونان لكل هوية.
- الاستضافة على GitHub Pages لا تسمح بضبط ترويسات HTTP. للحصول على CSP كاملة وHSTS وحماية الإطارات انشر على Netlify أو Cloudflare Pages وأضف ملف `_headers`.
- Tailwind يعمل عبر CDN. للأداء الأفضل يمكن توليد ملف CSS ثابت بالأمر `npx tailwindcss -i in.css -o out.css --minify`.

## النشر على GitHub Pages

1. ارفع `index.html` و`README.md` و`firestore.rules` إلى المستودع.
2. **Settings ← Pages**، اختر الفرع `main` والمجلد `/ (root)`، ثم احفظ.
3. بعد دقائق يصبح الموقع متاحاً على الرابط أعلاه.
